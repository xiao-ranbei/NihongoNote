3数据模型与稳定 ID

ID 全部可推导，偏移全部是相对原文的 UTF-16 偏移——前端永不靠字符串搜索定位。

表 / 对象关键字段说明
documents id, source_text, status, content_type(_source), content_blocks_json 保存后原文不可变；status 为 draft / analyzing / ready / failed
segments id = docId:segment:N, start_offset, end_offset, speaker, status, error_message 分句结果；queued / processing / completed / failed，失败原因直接可读
segment_analyses segment_id, result_json, usage_json, prompt_version, provider/model 1:1 存分析结果；usage 按批次去重后用于费用估算
analysis_revisions segment_id, revision, override_json 人工修正只存增量，永不覆盖 AI 原始结果
vocabulary_cache term, translation 译中缓存；命中后零本地推理
app_settings key（llm / contentDictionary / glossTranslation）, value(JSON) 覆盖 .env；清空 llm 键即回落环境变量
audio_assets / recordings — TTS 与跟读预留，当前无实现

4成本治理与可靠性

降本三件套（都在本地完成）

  • 形态素填事实字段，砍掉约 30% 模型输出
  • 固定用法库直接命中助词 / 功能词 / 句末模板
  • 内容词词典层：覆盖率 47.8% → 92.7%
  • 档位制 minimal / standard（默认）/ full，只改 prompt 与系数

可靠性机制

  • 预览零 LLM，分析前必须用户确认（LLM-011）
  • 按估算成本装箱 + 0.77 安全系数，避免长句段被截断
  • AbortController 取消在途请求，已完成段保留
  • 启动恢复 processing → queued，断点续跑
  • schema default(null)：漏字段降级，不整段作废

失败分类（都会落到段级 error_message）

  • provider 整批异常 → 自动重试 1 次
  • 逐段 schema / 边界不符 → 不重试（系统性偏差）
  • 本地模型未启动 → 探活后给可操作提示
  • 输出非法 JSON → 控制字符转义 → 引号修复

当前主要技术债

  • AnnotationRange 范围标注与四层点击循环未实现
  • CanonicalAnalysis / LevelExplanation 分层未实现
  • 导出、TTS、移动端抽屉未实现
  • App.tsx 偏大，做范围标注前需先拆
