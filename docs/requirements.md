### 1.0 本轮确认的范围基线（2026-08-28）

为先形成可验证、可扩展的基础，P1 不一次实现全部高级交互：

- **阅读 MVP**：先完成 token 和句子两层的稳定定位、视觉反馈和点击解析；语法范围、语气/态度范围以及四层循环点击不作为当前 MVP 的阻塞条件。
- **原文边界**：普通单换行、空行、说话人标签和句末标点规则完全按照本文档后续定义执行，不因 MVP 简化而改写原文。
- **取消语义**：取消分析必须调用后端取消流程，立即中止正在等待的云端请求，并停止尚未发出的后续请求；已完成句段保留，当前未完成句段回到可续跑状态。
- **内容类型**：用户选择优先；自动识别结果只作为建议，必须可以被用户覆盖。混合材料仍按区块保留解析开关。
- **人工修正**：首版优先标题、角色和解析字段；范围、区块和分句编辑先保留稳定 ID、版本和 API 边界。
- **对话关系**：首版保留相邻句的自然语言关系和回复理由；稳定多选标签、强度和 evidence range 后续再加入。
- **学习库**：首版先做搜索和分析状态筛选；内容类型筛选不作为首版阻塞条件。
- **本地数据**：不额外把本地 SQLite 数据库或 `.env` 纳入 Git 备份；代码和文档通过 Git 提交保留，运行数据继续由忽略规则保护。

### 1.1 P1 MVP：连续阅读、token 与句子

#### 连续阅读表面

- 原文、换行、标点和未解析区块都在同一个连续阅读框中展示；前端不能把文章视觉上拆成句子卡片。
- 普通单换行（不是空行、也不是新的说话人标签）视为排版换行：必须保留并显示，但不自动创建新的段落或句子。
- 空行（连续两个或更多换行）必须保留为视觉空白，并将其两侧划分为独立段落/区块。
- “李：”“田中部长：”“A:”等说话人标签保留在原文显示中，但单独存储为 speaker 字段，不参与日语分词、语法和 AI 解析。
- 句子范围包含句末标点（如“。」「？」「！”），但不包含说话人标签和段落换行；范围前后的留白只用于视觉间距。
- 后端仍可按区块、句子和任务段落处理，但这些内部边界不能破坏阅读表面的连续性。
- 保存与深度分析分为两个动作：保存后自动进行本地分段/分词等免费预处理，但用户必须明确点击“开始 AI 分析”后才调用云端模型。
- 分析过程中取消必须中止当前云端请求并停止后续请求；已完成结果保留，未开始或未完成的句段回到待分析，之后可以继续分析剩余内容。

#### 两种视觉维度

P1 MVP 先实现句子层和 token 层。背景色块和线型的完整叠加规则作为后续扩展，但现在就按稳定的原文偏移和 ID 设计数据边界，避免未来重做定位。

- **句子背景色块**：覆盖完整句子，作为最外层和最底层的浅色背景；支持跨行显示。
- **词语类别色块**：普通词、助词、助动词/其他功能词和副词分别使用较浅的分类色块，覆盖在句子底色之上。
- 普通词默认覆盖句子中所有可识别词语；用户可以按词性筛选显示。显示筛选只影响视觉，不删除已有解析。
- **后续范围层**：跨多个词的语法、语气和态度范围使用 `AnnotationRange` 表示，覆盖对应 token 但不改变句子和 token 的稳定 ID；不为分句单独增加背景色。

完整四层扩展还包括以下视觉约定：
- **单层下划线**：普通词语。
- **双层下划线**：严格意义上的助词。
- **虚线下划线**：助动词和其他功能词。
- **独立线色的单层下划线**：副词，同时可以指出其在本句中修饰的范围。
- **单层波浪线**：跨多个词的语法结构；语法结构整体显示为一个结构块，内部仍保留词语/助词等线型。
- **双层波浪线**：语气、态度和隐含意义对应的原文范围。
- 类别颜色具有固定语义并必须配合图例；用户后续可以切换预设主题或调整颜色。线型和文字标签不能省略，不能只依赖颜色区分。

#### 后续完整交互层级和解析卡片

P1 MVP 的交互只要求点击句子或 token 后打开对应解析；以下四层循环、范围卡片和移动端适配属于后续扩展：

- 背景色块默认可见，点击后强化当前范围。
- 同一原文位置重复点击时，显示层级按“句子结构 → 词语/助词/副词 → 多词语法 → 语气/态度”四层循环；当前文字没有对应层级时跳过该层；点击其他位置重新从第一层开始，点击文章外关闭当前卡片。
- 悬浮只强化当前范围，不显示弹窗；点击句子、词语、助词、副词、语法或语气范围后显示对应的完整解析。
- 完整解析在桌面端使用跟随点击位置的锚点卡片，并在靠近视口边缘时自动换位，不能遮住触发位置的关键原文。
- 移动端使用底部抽屉或侧边面板承载完整解析，不依赖悬浮状态。
- 对话关系默认只显示当前句相关的上一句/下一句；需要查看更多关系时显式展开，避免长对话出现大量连接线。

### 1.2 多材料和混合区块

- 文章级类型由用户手动选择为主；系统自动识别只生成建议，用户可以覆盖为课文、普通文章、对话、新闻/说明文、笔记等。
- 同一篇文章可以包含标题、正文、对话、例句和注释。系统为段落/区块提供类型和“是否参与解析”的状态，用户可以手动调整。
- 标题、编号和中文注释默认只保留原样展示；正文和日语例句默认参与解析。被关闭解析的区块不得出现模型生成的彩色标注或解释。
- 词汇、句意、语法、语气和不确定性是通用解析字段；只有对话区块在具备角色或上下文依据时显示“上一句如何影响本句”等关系字段，不能为普通文章强行生成回复理由。
- 自动识别的区块类型、角色和关系都必须允许用户修正，并显示其来源或不确定性；首版不把自动识别当作最终事实。

### 1.3 学习库和人工修正

- 学习库展开时展示最近文章列表，并提供搜索和分析状态筛选；内容类型筛选作为后续扩展，第一版不引入文件夹。
- 桌面端折叠为窄侧栏/图标轨道并保留展开入口，手机端改为覆盖主内容的抽屉。
- 折叠状态保存到本机浏览器偏好，刷新或重新打开应用后保持。
- “编辑解析”是独立模式：首版先允许修改标题、角色、词义、词性、语法和解释；选中文本调整分句、合并/拆分区块和标注范围保留稳定版本边界，后续实现。
- 人工修正不能覆盖 AI 原始响应；重新分析时必须能区分并保留人工版本，避免用户修正被静默丢弃。

### 1.4 统一基础分析与等级解释层

目标等级不是另一套 token 或语法事实，而是同一份基础分析的教学表达参数：

```text
原文
 ↓
CanonicalAnalysis
 ├── token 边界与词语事实
 ├── 助词与语法事实
 ├── 句意、语气和对话上下文事实
 └── 可验证的原文范围与 evidence
        ↓
LevelExplanation(targetLevel)
 ├── 面向 N5/N4/N3/N2/N1 的说明深度
 ├── 术语和例子的复杂度
 └── 学习者可读的教学表达
```

- `CanonicalAnalysis` 只保存事实、结构、稳定 ID、偏移和原文证据，文章只生成一份。
- `LevelExplanation` 按目标等级生成或缓存，不得复制或改写 canonical token、范围和语法事实。
- 用户切换等级时，优先重新生成解释层，不重新分词、不重新绑定前端位置。
- 人工修正应区分“事实修正”（影响 canonical）和“表达修正”（只影响 level explanation）。
- 当前 `SegmentAnalysis` 是兼容现有实现的过渡载体；后续拆分时必须保留既有 segment/token ID 和 UTF-16 偏移。

## 二、LLM 服务接入需求

### 已确认的接入策略

1. P1 首先接入 DeepSeek 的 OpenAI-compatible API。
2. 内部统一使用 NihongoNote 自己的 `LlmProvider` 接口和版本化 JSON schema。
3. Anthropic-compatible API 需要保留接入能力，但不阻塞第一条可用分析链路。
4. 前端不直接请求任何 LLM 服务；API key、base URL、模型和协议只由本机 API 管理。
5. DeepSeek 只负责文本分析。

DeepSeek 官方入口：

- OpenAI-compatible：`https://api.deepseek.com`
- Anthropic-compatible：`https://api.deepseek.com/anthropic`

具体模型名称、限流规则和价格在实施时以[官方文档](https://api-docs.deepseek.com/)为准。

### LLM 功能需求

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| LLM-001 | 配置 LLM provider | 可在本机服务端配置 provider、protocol、base URL、model 和 API key；密钥不出现在前端 |
| LLM-002 | DeepSeek 首条链路 | 使用 DeepSeek OpenAI-compatible API 完成一段真实日语材料的分析 |
| LLM-003 | 结构化 JSON | 请求启用 JSON 输出，结果通过本地 schema 校验后才可保存 |
| LLM-004 | 原文绑定 | 模型返回的 segment/token ID 必须来自服务端输入，不能由前端用字符串搜索猜测 |
| LLM-005 | 空结果和截断处理 | 空内容、非法 JSON 或长度截断必须标记为失败并可重试，不得显示为完成 |
| LLM-006 | 协议可替换 | 增加 Anthropic-compatible adapter 时，不修改前端阅读器和持久化分析 schema |
| LLM-007 | 调用元数据 | 保存 provider、model、protocol、promptVersion、输入/输出用量、缓存命中和错误分类 |

DeepSeek JSON Output 需要在 prompt 中明确要求 JSON，并设置合理的 `max_tokens`；即使返回合法 JSON，也必须继续校验业务字段和原文 ID。

当前实现已覆盖 LLM-001、LLM-003、LLM-004、LLM-005 的基础链路，以及 DeepSeek OpenAI-compatible adapter；LLM-002 仍需使用真实 DeepSeek API key 和评估样本完成质量/费用验收。LLM-006（Anthropic-compatible adapter）属于后续阶段。API 重启恢复逻辑会将中断的 `processing` 句段重新置为可重试状态。

## 三、产品目标

### 目标

让学习者在不离开原文的情况下，理解“这句话是什么、为什么这样说、说话人是什么态度、下一句为什么这样接”。

### 非目标

第一版不包含：

- 公网注册、登录、多人协作或计费；
- 自动抓取任意网页；
- OCR、图片/PDF 识别；
- 以 Agent 对话窗口替代文章阅读器；
- 保证模型解释等同于语言学教材或人工教师结论。

## 四、核心用户流程

1. 打开本机 Web 应用。
2. 粘贴课文、普通文章、新闻/说明文、笔记或对话，填写标题；用户先选择内容类型，自动识别只作为建议。
3. 保存文章，系统自动进行本地分段/分词并生成区块预览；用户检查类型建议和“是否参与解析”的状态。
4. 用户明确点击“开始 AI 分析”，生成统一基础分析并查看句段进度；需要停止时点击“取消”，后端中止当前云端请求并停止后续请求，之后可继续剩余句段或单独重试失败句段。
5. 在一个连续的原文阅读框中阅读：
   - P1 MVP 先显示句子层和 token 层的定位与解析；
   - 完整版本再显示语法/语气范围、线型标记和四层循环卡片；
   - 目标等级只改变教学表达，不改变基础分析的 token、范围和事实；
   - 对话首版显示相邻句的自然语言关系和回复理由，不要求稳定标签或 evidence range。
6. 首版进入“编辑解析”模式时先修改标题、角色和解析字段；区块、分句和标注范围调整后续加入。
7. 从可折叠的学习库搜索、按分析状态筛选和打开历史文章，内容类型筛选后续加入。

## 五、功能需求

### 5.1 文档和文章阅读

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| DOC-001 | 粘贴日语学习材料 | 粘贴课文、普通文章、新闻/说明文、笔记或对话后保留换行、标点和原文顺序；普通单换行只作为排版换行，空行划分独立段落/区块，并可在分析前编辑 |

| DOC-003 | 显示分析进度 | 长文分析时显示已完成、进行中、失败和待处理段落，并由用户手动开始分析 |
| DOC-004 | 连续阅读框 | 原文、换行、标点和未解析区块在一个连续阅读框中显示，不能按句子拆成视觉卡片 |

| DOC-006 | 历史搜索和筛选 | 首版按标题、原文片段和分析状态搜索/筛选已保存文章；内容类型筛选后续加入，当前不提供难度筛选 |
| DOC-007 | 混合材料区块 | 标题/编号/中文注释默认保留原样，正文和日语例句默认解析；用户可按区块开关解析 |
| DOC-008 | P1 两层范围标注 | MVP 保留连续阅读框并显示句子层和 token 层；语法/语气范围使用稳定 ID 预留，后续再实现完整叠加；不为分句设置独立色块 |
| DOC-009 | 后续线型语言标注 | 完整版本再实现普通词、助词、功能词、副词、多词语法和语气的不同线型；线型规则必须与图例一致 |
| DOC-010 | 后续逐层点击 | 完整版本同一位置重复点击按句子结构 → 词语/助词/副词 → 多词语法 → 语气/态度循环，缺少层级时跳过 |
| DOC-011 | 后续悬浮和锚点解析 | MVP 先支持句子/token 点击解析；悬浮高亮、桌面锚点自动换位和移动端抽屉作为后续扩展 |
| DOC-012 | 对话关系按需显示 | 首版只保留有依据的相邻句自然语言关系和回复理由；稳定标签、强度、evidence range 和更多箭头后续加入，非对话材料不强行生成 |
| DOC-013 | 首版人工修正和版本保留 | 首版先修改标题、角色和解析字段；区块、分句、标注范围编辑后续加入，且 AI 原始结果始终可追溯 |

### 5.2 词语、助词和语法分析

P1 MVP 先保证句子和 token 两层的定位、点击和解析。完整版本再实现“背景范围”和“线型类别”分离：句子底色、词语类别色块和语法色块按层叠加，普通词、助词、功能词、副词和语法同时使用线型区分。跨多个词的语法必须有一个整体范围，内部词语仍可保留自己的线型。

每个可交互词语至少应能显示：

- 默认所有可识别词语都进入词语分析；
- 原文表面形；
- 原形/词典形；
- 假名读音；
- 词性；
- 中文释义；
- 活用前后形态（若适用）；
- 在当前句子中的具体作用；
- 不确定时的候选解释或置信提示。
- 用户可以按词性筛选词语标注；筛选不能删除原始分析结果。

助词和语法解释至少应能显示：

- 语法点名称；
- 本句中的连接方式；
- 本句中的功能和语义；
- 为什么不是常见的其他用法；
- 一句简短的替换/对比例句（模型能可靠生成时）。

副词至少应显示其词性、常见释义、读音和在本句中的修饰范围；其单层下划线颜色必须与普通词不同。

### 5.3 句子、语气和对话分析

每个句子至少应能显示：

- 自然中文译文；
- 用户主动请求时显示直译；
- 句子结构和关键语法；
- 会话功能和情绪/态度的基础说明；稳定的多选标签可以在后续版本补充；
- 语气强度等级和判断依据；
- 总体礼貌等级（随意 / 普通 / 礼貌 / 尊敬 / 自谦）；
- 具体语体和敬语形式标签；
- 省略、潜台词或上下文依赖；
- 如果是对话：首版使用自然语言说明上一句如何影响本句、本句为何采用这种回复；
- 对存在多种合理解释的内容明确标记不确定性。

模型输出必须包含原文句子 ID，前端不得依赖模型返回的字符串位置自行猜测绑定关系。
token 的边界、ID、surface 和字符偏移由本机服务生成并传给模型；模型返回的 token 必须逐项匹配本地边界。

对话关系不是所有文章的必填字段：对话区块在有角色和上下文依据时显示相邻句影响和回复理由；课文、新闻、说明文和笔记只显示适用的句意、结构、语气及不确定性。

首版不要求对话关系具备稳定标签、强度等级、evidence range 或可展开的全量箭头；这些字段必须在后续扩展时继续引用稳定的 segment/token ID。

### 5.4 对话角色

- 支持用户输入 `A:`、`B:` 或任意角色名。
- 未标注时，AI 可以推断角色，但必须允许用户修改。
- 第一版不要求根据年龄、性别或社会关系自动推断复杂设定；这些信息可作为可选备注。
- 首版只在当前句旁显示有依据的相邻句自然语言关系和回复理由；稳定关系标签、强度、evidence range 以及“展开关系”箭头后续加入。

### 5.5 数据管理

- 新建、重命名和删除文章。
- 保存分析提示词/解析协议版本，避免模型升级后无法追踪结果来源。
- 支持导出原文和解析 JSON，作为后续备份能力；若首版时间有限，导出可排在历史搜索之后。

### 5.6 后续 TTS 与标准朗读

以下是后续能力，不属于当前文本解析版本：

- 保留独立的 TTS provider 接口，前端和文本解析不绑定具体供应商。
- 支持标准、清晰的日语朗读发音。
- 支持按句子或段落播放、暂停、继续和从当前句开始。
- 根据标点、普通排版换行和对话轮次产生合理停顿。
- 支持调整语速；后续是否支持更多音高或语气参数由实际 TTS 能力决定。
- 生成的音频结果应记录 provider、voice、语速、发音/韵律参数、格式和文本版本。
- 音频可以按文本、voice、语速、韵律参数和格式缓存。
- 当前不做浏览器录音、跟读录音、录音保存或录音回放。

## 六、建议的数据结构

等级选择属于教学表达层，不应复制基础分析。建议从数据模型上保留两个明确边界：

```text
CanonicalAnalysis
  id, sourceVersion, segmentId, tokenizerVersion
  tokenFacts, grammarFacts, sentenceMeaningFacts
  toneFacts, politenessFacts, dialogueContextFacts
  annotationRanges, evidenceTokenIds

LevelExplanation
  id, canonicalAnalysisId, targetLevel, explanationVersion
  translation, teachingSummary, vocabularyNotes, examples
```

`CanonicalAnalysis` 是同一篇文章唯一的事实和结构来源；`LevelExplanation` 可以按 N5/N4/N3/N2/N1 生成或缓存。切换等级时只重新生成解释层，不重新分词、不改变范围和前端定位。

```text
Document
  id, title, sourceText, targetLevel(explanation preference), contentType
  createdAt, updatedAt

ContentBlock
  id, documentId, index, kind, text, startOffset, endOffset
  analysisEnabled, detectedType, selectedType, speaker

Segment
  id, documentId, blockId, index, text, speaker, status
  startOffset, endOffset
  translation, literalTranslation, grammarSummary
  conversationFunctionTags, attitudeTags, toneStrength(weak|medium|strong), toneEvidence
  politenessLevel, registerTags
  impliedMeaning, replyReason, contextNote

TokenAnalysis
  id, segmentId, start, end, surface, lemma, reading
  partOfSpeech, conjugation, gloss, particleFunction
  grammarPoint, explanation, confidence

AnnotationRange
  id, segmentId, start, end, kind, style, targetTokenIds
  explanation, evidenceTokenIds, confidence, source, revisionId

AudioAsset
  id, segmentId, provider, voice, format, path
  speed, prosody, ssmlVersion, sourceTextHash, createdAt

```

`politenessLevel` 使用“随意 / 普通 / 礼貌 / 尊敬 / 自谦”五档；`registerTags` 可包含“普通体、
敬体、尊敬语、自谦语、丁寧语/礼貌表达、郑重语、商务正式表达”。

`start` 和 `end` 应由服务端分词结果生成，并以稳定的 Unicode 字符偏移保存。前端不能只依赖视觉上的字符串搜索，以免重复词语绑定到错误位置。

`AnnotationRange` 用来表示跨多个 token 的分句、语法和语气范围；`TokenAnalysis` 继续表示确定性的词语边界。`source` 至少区分 AI 和 user，人工修正通过 revision 或快照保留原始 AI 结果。原文文本本身不因标注修正而改写，所有范围都必须能回溯到稳定的 block/segment/token ID。

当前 `SegmentAnalysis` 可以作为兼容现有实现的过渡载体，但新字段和接口不得把 `targetLevel` 混入 token、范围或语法事实；后续拆分时应通过 `canonicalAnalysisId` 和 `explanationVersion` 关联两个层次。

## 七、非功能需求

### 可靠性

- 每个分析段落有独立状态：`queued`、`processing`、`completed`、`failed`。
- 网络错误、限流和模型结构化输出失败必须对用户可见。
- 重试要有次数上限和退避，不得无限重试或静默返回空结果。
- 只有通过 schema 校验的结果才能写入完成状态。
- 取消分析必须中止当前的云端请求，并阻止队列继续发出新的请求；已完成句段不得回滚。

### 隐私和安全

- 服务只监听本机地址，第一版不暴露公网。
- LLM/TTS API 密钥只存在服务端环境变量，不发送到浏览器。
- 默认日志不记录完整文章或 API 密钥。
- 开发者调试日志必须显式开启；开启后可以记录发送给 provider 的 messages 和响应以排查协议问题，
  但 Authorization header 和 API key 永远不得写入，调试结束后应关闭并删除日志。

### 可维护性

- LLM、TTS 和分词器都通过适配器隔离；当前 TTS provider 保持未启用。
- 当前 token 边界可使用 Node `Intl.Segmenter`，后续可替换为更精细的日语形态素分析器而不改变前端绑定协议。
- LLM 协议通过 adapter 隔离；业务层不得依赖 OpenAI 或 Anthropic 的响应对象。
- 分析输出使用版本化 JSON schema。
- 前端渲染层不直接拼接模型 Markdown 作为结构化数据源。
- 标注渲染使用稳定偏移和区间切分；不得通过嵌套可点击按钮实现重叠范围，以免点击目标和无障碍语义冲突。
- 颜色不能作为唯一分类依据；图例、线型、焦点样式和文字标签必须同步可用。

## 八、验收样例

准备至少三类真实材料：

1. 一段包含多个助词和活用的普通文章；
2. 一段包含省略、委婉表达和上下文依赖的双人对话；
3. 一篇超过单次模型上下文舒适范围的长文。

每类材料都应通过以下检查：

- 原文顺序、换行和标点不丢失；
- 词语和句子定位稳定；
- 解析能指出具体原文证据；
- 长文失败可单段重试；
- API 出错时显示原因，而不是伪装成“分析完成”。
- 使用 DeepSeek OpenAI-compatible API 时，结构化结果能够通过 schema 校验并绑定到正确句段。
- 将 provider 配置为未实现的协议时，服务启动或请求失败必须给出明确提示，不能静默切换到其他模型。
- 课文、普通文章、新闻/说明文、笔记和对话都能保留其正文结构；非对话材料不会出现无依据的“接话理由”。
- P1 MVP 的连续阅读框能稳定显示句子层和 token 层，点击句子或 token 能打开对应解析；不因内部句段任务拆成视觉卡片。
- 完整版本再验收句子底色、词语类别色块、语法/语气范围、线型和四层循环；所有范围继续引用稳定 ID。
- 取消分析会中止当前云端请求，不清除已完成句段，重新开始只处理待分析或失败句段。
- 首版修改标题、角色或解析字段后仍能查看 AI 原始版本；区块、分句和标注范围编辑后续验收。
- 学习库折叠状态跨刷新保留，首版搜索和分析状态筛选结果正确；内容类型筛选和难度筛选后续加入。
- 切换目标等级只重新生成 `LevelExplanation`，不复制或改变 `CanonicalAnalysis` 的 token、范围和事实。
