### 1.1 连续阅读和分层标注

#### 连续阅读表面

- 原文、换行、标点和未解析区块都在同一个连续阅读框中展示；前端不能把文章视觉上拆成句子卡片。
- 普通单换行（不是空行、也不是新的说话人标签）视为排版换行：必须保留并显示，但不自动创建新的段落或句子。
- 空行（连续两个或更多换行）必须保留为视觉空白，并将其两侧划分为独立段落/区块。
- “李：”“田中部长：”“A:”等说话人标签保留在原文显示中，但单独存储为 speaker 字段，不参与日语分词、语法和 AI 解析。
- 句子范围包含句末标点（如“。」「？」「！”），但不包含说话人标签和段落换行；范围前后的留白只用于视觉间距。
- 后端仍可按区块、句子和任务段落处理，但这些内部边界不能破坏阅读表面的连续性。
- 保存与深度分析分为两个动作：保存后自动进行本地分段/分词等免费预处理，但用户必须明确点击“开始 AI 分析”后才调用云端模型。
- 分析过程中取消只影响未完成部分：已完成结果保留，未开始或未完成的句段回到待分析，之后可以继续分析剩余内容。

#### 两种视觉维度

背景色块和线型分别表达范围与语言角色。背景色块允许按确定的层级叠加，句子始终是最底层：

- **句子背景色块**：覆盖完整句子，作为最外层和最底层的浅色背景；支持跨行显示。
- **词语类别色块**：普通词、助词、助动词/其他功能词和副词分别使用较浅的分类色块，覆盖在句子底色之上。
- 普通词默认覆盖句子中所有可识别词语；用户可以按词性筛选显示。显示筛选只影响视觉，不删除已有解析。
- **语法背景色块**：跨多个词的语法结构使用结构色块，覆盖对应词语色块；不为分句单独增加背景色。
- **单层下划线**：普通词语。
- **双层下划线**：严格意义上的助词。
- **虚线下划线**：助动词和其他功能词。
- **独立线色的单层下划线**：副词，同时可以指出其在本句中修饰的范围。
- **单层波浪线**：跨多个词的语法结构；语法结构整体显示为一个结构块，内部仍保留词语/助词等线型。
- **双层波浪线**：语气、态度和隐含意义对应的原文范围。
- 类别颜色具有固定语义并必须配合图例；用户后续可以切换预设主题或调整颜色。线型和文字标签不能省略，不能只依赖颜色区分。

#### 交互层级和解析卡片

- 背景色块默认可见，点击后强化当前范围。
- 同一原文位置重复点击时，显示层级按“句子结构 → 词语/助词/副词 → 多词语法 → 语气/态度”四层循环；当前文字没有对应层级时跳过该层；点击其他位置重新从第一层开始，点击文章外关闭当前卡片。
- 悬浮只强化当前范围，不显示弹窗；点击句子、词语、助词、副词、语法或语气范围后显示对应的完整解析。
- 完整解析在桌面端使用跟随点击位置的锚点卡片，并在靠近视口边缘时自动换位，不能遮住触发位置的关键原文。
- 移动端使用底部抽屉或侧边面板承载完整解析，不依赖悬浮状态。
- 对话关系默认只显示当前句相关的上一句/下一句；需要查看更多关系时显式展开，避免长对话出现大量连接线。

### 1.2 多材料和混合区块

- 文章级类型默认由系统自动识别，用户可以手动改为课文、普通文章、对话、新闻/说明文、笔记等。
- 同一篇文章可以包含标题、正文、对话、例句和注释。系统为段落/区块提供类型和“是否参与解析”的状态，用户可以手动调整。
- 标题、编号和中文注释默认只保留原样展示；正文和日语例句默认参与解析。被关闭解析的区块不得出现模型生成的彩色标注或解释。
- 词汇、句意、语法、语气和不确定性是通用解析字段；只有对话区块在具备角色或上下文依据时显示“上一句如何影响本句”等关系字段，不能为普通文章强行生成回复理由。
- 自动识别的区块类型、角色和关系都必须允许用户修正，并显示其来源或不确定性。

### 1.3 学习库和人工修正

- 学习库展开时展示最近文章列表，并提供搜索、内容类型和分析状态筛选；第一版不引入文件夹。
- 桌面端折叠为窄侧栏/图标轨道并保留展开入口，手机端改为覆盖主内容的抽屉。
- 折叠状态保存到本机浏览器偏好，刷新或重新打开应用后保持。
- “编辑解析”是独立模式：用户可以选中文本调整分句、合并/拆分区块和标注范围，并在详情面板编辑词义、词性、语法和解释。
- 人工修正不能覆盖 AI 原始响应；重新分析时必须能区分并保留人工版本，避免用户修正被静默丢弃。

## 二、LLM 服务接入需求

### 已确认的接入策略

1. P1 首先接入 DeepSeek 的 OpenAI-compatible API。
2. 内部统一使用 NihongoNote 自己的 `LlmProvider` 接口和版本化 JSON schema。
3. Anthropic-compatible API 需要保留接入能力，但不阻塞第一条可用分析链路。
4. 前端不直接请求任何 LLM 服务；API key、base URL、模型和协议只由本机 API 管理。
5. DeepSeek 只负责文本分析。

DeepSeek 官方入口：

- OpenAI-compatible：`https://api.deepseek.com`
- Anthropic-compatible：`https://api.deepseek.com/anthropic`

具体模型名称、限流规则和价格在实施时以[官方文档](https://api-docs.deepseek.com/)为准。

### LLM 功能需求

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| LLM-001 | 配置 LLM provider | 可在本机服务端配置 provider、protocol、base URL、model 和 API key；密钥不出现在前端 |
| LLM-002 | DeepSeek 首条链路 | 使用 DeepSeek OpenAI-compatible API 完成一段真实日语材料的分析 |
| LLM-003 | 结构化 JSON | 请求启用 JSON 输出，结果通过本地 schema 校验后才可保存 |
| LLM-004 | 原文绑定 | 模型返回的 segment/token ID 必须来自服务端输入，不能由前端用字符串搜索猜测 |
| LLM-005 | 空结果和截断处理 | 空内容、非法 JSON 或长度截断必须标记为失败并可重试，不得显示为完成 |
| LLM-006 | 协议可替换 | 增加 Anthropic-compatible adapter 时，不修改前端阅读器和持久化分析 schema |
| LLM-007 | 调用元数据 | 保存 provider、model、protocol、promptVersion、输入/输出用量、缓存命中和错误分类 |

DeepSeek JSON Output 需要在 prompt 中明确要求 JSON，并设置合理的 `max_tokens`；即使返回合法 JSON，也必须继续校验业务字段和原文 ID。

当前实现已覆盖 LLM-001、LLM-003、LLM-004、LLM-005 的基础链路，以及 DeepSeek OpenAI-compatible adapter；LLM-002 仍需使用真实 DeepSeek API key 和评估样本完成质量/费用验收。LLM-006（Anthropic-compatible adapter）属于后续阶段。API 重启恢复逻辑会将中断的 `processing` 句段重新置为可重试状态。

## 三、产品目标

### 目标

让学习者在不离开原文的情况下，理解“这句话是什么、为什么这样说、说话人是什么态度、下一句为什么这样接”。

### 非目标

第一版不包含：

- 公网注册、登录、多人协作或计费；
- 自动抓取任意网页；
- OCR、图片/PDF 识别；
- 以 Agent 对话窗口替代文章阅读器；
- 保证模型解释等同于语言学教材或人工教师结论。

## 四、核心用户流程

1. 打开本机 Web 应用。
2. 粘贴课文、普通文章、新闻/说明文、笔记或对话，填写标题；内容类型默认自动识别，也可以手动覆盖。
3. 保存文章，系统自动进行本地分段/分词并生成区块预览；用户检查区块类型和“是否参与解析”的状态。
4. 用户明确点击“开始 AI 分析”，一次生成所有已启用区块的完整解析并查看句段进度；需要停止时点击“取消”，之后可继续剩余句段或单独重试失败句段。
5. 在一个连续的原文阅读框中阅读：
   - 看到句子底色、词语类别色块和语法结构的浅色范围；
   - 看到普通词、助词、功能词、副词、多词语法和语气的线型标记；
   - 悬浮只高亮当前范围，点击同一位置按句子结构、词语、语法、语气顺序逐层打开解析；
   - 在锚点卡片中查看词形、原形、读音、词性、词义、活用、本句作用、语法点和不确定性；
   - 点击句子范围查看自然中文译文、语法结构、态度标签、语气强度、礼貌程度、潜台词和上下文；直译在用户主动展开时按需生成；
   - 对话中默认在当前句旁显示相邻句关系标签和自然语言原因，点击“展开关系”后再显示句子之间的箭头；普通文章不显示无依据的回复理由。
6. 需要更正时进入“编辑解析”模式，调整区块、分句、标注范围和解释字段。
7. 从可折叠的学习库搜索、筛选和打开历史文章，继续复习。

## 五、功能需求

### 5.1 文档和文章阅读

| ID | 需求 | 验收标准 |

| DOC-011 | 悬浮和锚点解析 | 悬浮只高亮当前范围、不显示弹窗；桌面端点击句子、词语、助词、副词、语法或语气范围显示可自动换位的锚点卡片，移动端显示底部抽屉或侧边面板 |
| DOC-012 | 对话关系按需显示 | 对话默认只展示当前句相关的上一句/下一句关系，可显式展开更多；非对话材料不强行生成回复理由 |
| DOC-013 | 人工修正和版本保留 | 独立编辑模式支持调整区块、分句、标注范围和解析字段，且 AI 原始结果始终可追溯 |

### 5.2 词语、助词和语法分析

视觉层级必须遵守“背景范围”和“线型类别”分离的规则。句子底色、词语类别色块和语法色块按层叠加；普通词、助词、功能词、副词和语法同时使用线型区分。跨多个词的语法必须有一个整体范围，内部词语仍可保留自己的线型。

每个可交互词语至少应能显示：

- 默认所有可识别词语都进入词语分析；
- 原文表面形；
- 原形/词典形；
- 假名读音；
- 词性；
- 中文释义；
- 活用前后形态（若适用）；
- 在当前句子中的具体作用；
- 不确定时的候选解释或置信提示。
- 用户可以按词性筛选词语标注；筛选不能删除原始分析结果。

助词和语法解释至少应能显示：

- 语法点名称；
- 本句中的连接方式；
- 本句中的功能和语义；
- 为什么不是常见的其他用法；
- 一句简短的替换/对比例句（模型能可靠生成时）。

副词至少应显示其词性、常见释义、读音和在本句中的修饰范围；其单层下划线颜色必须与普通词不同。

### 5.3 句子、语气和对话分析

每个句子至少应能显示：

- 自然中文译文；
- 用户主动请求时显示直译；
- 句子结构和关键语法；
- 会话功能标签和情绪/态度标签；两层都允许多个标签；
- 语气强度等级和判断依据；
- 总体礼貌等级（随意 / 普通 / 礼貌 / 尊敬 / 自谦）；
- 具体语体和敬语形式标签；
- 省略、潜台词或上下文依赖；
- 如果是对话：上一句如何影响本句、本句为何采用这种回复；
- 对存在多种合理解释的内容明确标记不确定性。

模型输出必须包含原文句子 ID，前端不得依赖模型返回的字符串位置自行猜测绑定关系。
token 的边界、ID、surface 和字符偏移由本机服务生成并传给模型；模型返回的 token 必须逐项匹配本地边界。

对话关系不是所有文章的必填字段：对话区块在有角色和上下文依据时显示相邻句影响和回复理由；课文、新闻、说明文和笔记只显示适用的句意、结构、语气及不确定性。

### 5.4 对话角色

- 支持用户输入 `A:`、`B:` 或任意角色名。
- 未标注时，AI 可以推断角色，但必须允许用户修改。
- 第一版不要求根据年龄、性别或社会关系自动推断复杂设定；这些信息可作为可选备注。
- 默认只在当前句旁显示其相邻句的关系标签和自然语言原因；用户主动点击“展开关系”后，才显示相邻句之间的箭头及更多关系。

### 5.5 数据管理

- 新建、重命名和删除文章。
- 保存分析提示词/解析协议版本，避免模型升级后无法追踪结果来源。
- 支持导出原文和解析 JSON，作为后续备份能力；若首版时间有限，导出可排在历史搜索之后。

### 5.6 后续 TTS 与标准朗读

以下是后续能力，不属于当前文本解析版本：

- 保留独立的 TTS provider 接口，前端和文本解析不绑定具体供应商。
- 支持标准、清晰的日语朗读发音。
- 支持按句子或段落播放、暂停、继续和从当前句开始。
- 根据标点、普通排版换行和对话轮次产生合理停顿。
- 支持调整语速；后续是否支持更多音高或语气参数由实际 TTS 能力决定。
- 生成的音频结果应记录 provider、voice、语速、发音/韵律参数、格式和文本版本。
- 音频可以按文本、voice、语速、韵律参数和格式缓存。
- 当前不做浏览器录音、跟读录音、录音保存或录音回放。

## 六、建议的数据结构

```text
Document
  id, title, sourceText, targetLevel, contentType, createdAt, updatedAt

ContentBlock
  id, documentId, index, kind, text, startOffset, endOffset
  analysisEnabled, detectedType, selectedType, speaker

Segment
  id, documentId, blockId, index, text, speaker, status
  startOffset, endOffset
  translation, literalTranslation, grammarSummary
  conversationFunctionTags, attitudeTags, toneStrength(weak|medium|strong), toneEvidence
  politenessLevel, registerTags
  impliedMeaning, replyReason, contextNote

TokenAnalysis
  id, segmentId, start, end, surface, lemma, reading
  partOfSpeech, conjugation, gloss, particleFunction
  grammarPoint, explanation, confidence

AnnotationRange
  id, segmentId, start, end, kind, style, targetTokenIds
  explanation, evidenceTokenIds, confidence, source, revisionId

AudioAsset
  id, segmentId, provider, voice, format, path
  speed, prosody, ssmlVersion, sourceTextHash, createdAt

```

`politenessLevel` 使用“随意 / 普通 / 礼貌 / 尊敬 / 自谦”五档；`registerTags` 可包含“普通体、
敬体、尊敬语、自谦语、丁寧语/礼貌表达、郑重语、商务正式表达”。

`start` 和 `end` 应由服务端分词结果生成，并以稳定的 Unicode 字符偏移保存。前端不能只依赖视觉上的字符串搜索，以免重复词语绑定到错误位置。

`AnnotationRange` 用来表示跨多个 token 的分句、语法和语气范围；`TokenAnalysis` 继续表示确定性的词语边界。`source` 至少区分 AI 和 user，人工修正通过 revision 或快照保留原始 AI 结果。原文文本本身不因标注修正而改写，所有范围都必须能回溯到稳定的 block/segment/token ID。

## 七、非功能需求

### 可靠性

- 每个分析段落有独立状态：`queued`、`processing`、`completed`、`failed`。
- 网络错误、限流和模型结构化输出失败必须对用户可见。
- 重试要有次数上限和退避，不得无限重试或静默返回空结果。
- 只有通过 schema 校验的结果才能写入完成状态。

### 隐私和安全

- 服务只监听本机地址，第一版不暴露公网。
- LLM/TTS API 密钥只存在服务端环境变量，不发送到浏览器。
- 默认日志不记录完整文章或 API 密钥。

### 可维护性

- LLM、TTS 和分词器都通过适配器隔离；当前 TTS provider 保持未启用。
- 当前 token 边界可使用 Node `Intl.Segmenter`，后续可替换为更精细的日语形态素分析器而不改变前端绑定协议。
- LLM 协议通过 adapter 隔离；业务层不得依赖 OpenAI 或 Anthropic 的响应对象。
- 分析输出使用版本化 JSON schema。
- 前端渲染层不直接拼接模型 Markdown 作为结构化数据源。
- 标注渲染使用稳定偏移和区间切分；不得通过嵌套可点击按钮实现重叠范围，以免点击目标和无障碍语义冲突。
- 颜色不能作为唯一分类依据；图例、线型、焦点样式和文字标签必须同步可用。

## 八、验收样例

准备至少三类真实材料：

1. 一段包含多个助词和活用的普通文章；
2. 一段包含省略、委婉表达和上下文依赖的双人对话；
3. 一篇超过单次模型上下文舒适范围的长文。

每类材料都应通过以下检查：

- 原文顺序、换行和标点不丢失；
- 词语和句子定位稳定；
- 解析能指出具体原文证据；
- 长文失败可单段重试；
- API 出错时显示原因，而不是伪装成“分析完成”。
- 使用 DeepSeek OpenAI-compatible API 时，结构化结果能够通过 schema 校验并绑定到正确句段。
- 将 provider 配置为未实现的协议时，服务启动或请求失败必须给出明确提示，不能静默切换到其他模型。
- 课文、普通文章、新闻/说明文、笔记和对话都能保留其正文结构；非对话材料不会出现无依据的“接话理由”。
- 连续阅读框中句子底色、词语类别色块和语法色块按层显示，不为分句增加独立色块；多词语法有整体范围，词语/助词/功能词/副词/语气线型符合图例。
- 同一位置重复点击能按句子结构、词语、语法、语气四层循环并跳过不存在的层级，锚点卡片能在视口边缘自动换位，触屏端无需悬浮也能打开详情。
- 取消分析不会清除已完成句段，重新开始只处理待分析或失败句段。
- 人工修正后重新分析仍能查看 AI 原始版本和当前用户版本。
- 学习库折叠状态跨刷新保留，搜索和内容类型/分析状态筛选结果正确；当前不提供难度筛选。
