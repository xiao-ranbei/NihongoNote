# 迭代路线图

**目标**：先做一个能长期自用的本地学习闭环，再扩展到 Agent、浏览器扩展和多设备同步。
**更新**：2026-08-28，确定 DeepSeek OpenAI-compatible API 为首条 LLM 实现路径，并将 P1 收敛为 token + 句子两层 MVP。

## 一、阶段总览

| 阶段 | 主要交付 | 估算周期 | 完成标志 |
| --- | --- | --- | --- |
| P0 验证和骨架 | 样本集、项目骨架、DeepSeek/OpenAI-compatible provider、结构化分析 API、最小存储 | 1-2 天 | 能在本机启动并成功完成一次结构化分析 |
| P1 MVP 交互式解析 | 连续文章阅读器、句子/token 两层定位、用户选择类型、基础句子/词语解析、可中止云端请求、学习库搜索和分析状态筛选 | 待按编辑器复杂度重新估算 | 三类真实材料的基础定位和分析闭环通过验收 |
| P1 后续增强 | 完整范围标注、四层点击、锚点/移动端卡片、区块/分句/范围编辑、等级解释层切换、内容类型筛选 | 待 MVP 验收后拆分 | 在不改变 canonical ID 的前提下逐项完成 |
| P2 自用质量 | 扩展搜索/批量管理、删除/导出、缓存、提示词版本、错误体验 | 5-10 个工作日 | 连续使用一周不需要手工修复数据 |
| P3 扩展 | TTS 标准朗读/播放、Agent/skill、浏览器扩展、多设备同步或公网部署 | 按需 | 以真实学习收益为准，不预设一次完成 |

周期是单人开发、使用现成云服务、没有公网账号体系的粗略估算。当前先以 P1 MVP 验证基础定位、分析和取消闭环，再按真实使用反馈拆分完整范围渲染、编辑版本和等级解释层；模型选型可能增加时间。

## 二、P0：验证和骨架

当前已收录两篇真实商务对话，见[日语解析评估样本集](evaluation-corpus.md)。P0 仍需要普通文章、课文或混合材料，以避免模型只针对商务敬语场景优化。

### 工作项

基础骨架、基于官方 OpenAI SDK 的 DeepSeek OpenAI-compatible adapter、JSON schema 校验、句段分析任务、进度、取消和失败句段重试已经实现；真实供应商 key 的固定样本验证仍需继续。

- 收集至少三篇真实材料；
- 以 `deepseek-v4-flash`、`thinking` 和 `reasoning_effort` 配置验证 DeepSeek OpenAI-compatible API，使用真实材料做质量/费用验证；
- 使用 `LLM_DEBUG_LOGGING` 检查实际请求 messages、推理参数、响应耗时和失败原因；
- 记录 provider、protocol、model、promptVersion、用量和错误分类。

### 不做

- 不做复杂 UI；
- 不做用户系统；
- 不做公网部署；

### 退出条件

- 一篇短文章能返回可校验 JSON；
- 返回结果能准确关联到句子 ID；
- API 错误不会被伪装成成功；
- DeepSeek 可以通过环境变量配置并完成一次真实分析；
- provider 和模型可以通过环境变量切换，未实现协议会明确报错；
- 空 JSON、非法 JSON 和长度截断都会进入失败/重试路径。

### P0 的协议边界

- DeepSeek OpenAI-compatible 是 P1 的必做路径；
- Anthropic-compatible 先只写入 adapter 设计，不要求在 P0 完成；
- 不允许业务层直接依赖 OpenAI 或 Anthropic SDK 的响应对象；

## 三、P1：交互式解析

### 当前实现状态（2026-08-28）

P1 MVP 已完成以下闭环：

- 连续阅读框中的句子/token 两层稳定定位和点击解析；
- 用户手动选择内容类型，服务端提供自动识别建议；
- 用户手动启动分析，取消时中止当前云端请求并停止后续请求；
- 失败句段单独重试，已完成结果在取消或失败时保留；
- 首版标题、角色和解析字段修正，并保留 AI 原始版本；
- 学习库折叠状态、搜索和分析状态筛选。

已完成一段真实 DeepSeek 商务发言的连通性和 schema 验证（3 个句子均成功）；完整固定样本的质量/费用验收仍未完成。完整范围叠加、四层点击、区块/分句/范围编辑和等级解释层切换按下方 P1 后续增强推进。

### P1 MVP 交付顺序

1. 接入并验证 DeepSeek OpenAI-compatible adapter 和分析 API（已完成单段真实 key 验证，待完整样本回归）；
2. 粘贴、编辑和保存文章；用户手动选择内容类型，自动识别只生成建议；
3. 按文档规则完成日语句子切分、说话人识别和稳定的 UTF-16 偏移；
4. 在连续阅读框中保留原文、换行、标点和未解析区块，并实现句子层和 token 层定位；
5. 在统一基础分析中提供句意、词语、助词、语法、语气和有依据的自然语言对话关系；
6. 用户手动启动 AI 分析，显示进度；取消时中止当前云端请求并停止后续请求，支持失败句段重试；
7. 首版支持修改标题、角色和解析字段，并保留 AI 原始版本；
8. 学习库支持折叠、搜索和分析状态筛选，内容类型筛选暂不阻塞 MVP；
9. 保留 `targetLevel` 作为教学表达偏好，建立 `CanonicalAnalysis` 与 `LevelExplanation` 的稳定接口边界。

### P1 后续增强顺序

1. 将当前过渡性的分析载体拆分为 canonical 事实和等级解释，并支持切换等级只重生成解释层；
2. 增加语法/语气范围、背景叠加、线型标注和四层点击循环；
3. 增加桌面锚点自动换位、移动端抽屉和完整的 hover/focus 交互；
4. 增加区块、分句和标注范围编辑，以及事实版本/表达版本冲突处理；
5. 增加稳定对话标签、强度、evidence range 和可展开关系箭头；
6. 增加学习库内容类型筛选。

### P1 MVP 质量门槛

- 不以模型返回的 Markdown 位置绑定 token；
- 对相同词语重复出现的句子，点击位置不能串到另一处；
- 不确定解释必须可见；
- 一段失败不会清空已经完成的段落；
- 文章在一个连续阅读框中显示，不能因内部句段任务而拆成视觉卡片；
- MVP 至少提供句子层和 token 层的稳定定位与点击解析；
- 标题/注释默认不解析，正文/日语例句默认解析，混合区块可以手动调整；
- 内容类型以用户选择为准，自动识别只作为建议；
- 对话关系首版使用有依据的相邻句自然语言说明，普通文章不出现无依据的回复理由；
- 取消分析会中止当前云端请求，不清除已完成结果，重新启动只处理待分析或失败句段；
- 首版修改标题、角色和解析字段后仍可查看 AI 原始版本；
- 学习库折叠状态跨刷新保留，搜索和分析状态筛选结果正确。

完整范围叠加、线型、四层循环、锚点换位、移动端抽屉和范围编辑属于 P1 后续增强的独立验收项，不阻塞 MVP。

## 四、P2：可长期使用的质量增强

- 扩展搜索、标签和批量管理（首版只承诺搜索和分析状态筛选）；
- 文章重命名和删除；
- 导出 JSON 和原文；
- 分析缓存和费用统计；
- provider 限流、超时和断点续跑；
- 在 P1 稳定后评估并实现 Anthropic-compatible adapter；
- 完善 `LevelExplanation` 的 N5-N1/自动表达切换，不重新生成 `CanonicalAnalysis`；
- 扩展修正历史、范围冲突提示和批量应用能力；
- 用固定回归样本检查 prompt 或模型升级后的结果。

## 五、P3：后续扩展

### TTS 标准朗读（待排期）

- 接入独立的 TTS provider；
- 标准、清晰的日语发音；
- 按句子或段落播放、暂停、继续和从当前句开始；
- 根据标点、普通排版换行和对话轮次产生合理停顿；
- 支持语速调整；
- 记录生成参数并按文本和参数缓存；
- 不包含浏览器录音、跟读录音、录音保存或录音回放。

### Agent/skill

- 将结构化分析协议提取为可复用 skill；
- 让 Web 后端和 Agent 共用 provider-neutral 的分析 schema；
- 从 Web 阅读器把当前句子发送给 Agent 深入追问；
- 批量处理收藏文章；
- 保持与 Web API 相同的 schema 和版本控制。

### 浏览器扩展

- 用户在网页中选中文字；
- 发送到本机 Web API；
- 在侧边栏展示解析，不直接把 API 密钥放进扩展；
- 必须单独评估网页权限和隐私风险。

## 六、验收和回归计划

每次更换模型、提示词或分词器时，重新运行固定样本：

1. 助词多、活用复杂的普通文章或课文；
2. 标题、例句、注释和正文混合的教材材料；
3. 委婉拒绝、缓和表达和省略主语的对话；
4. 长文分块、取消和中途失败场景；
5. 重复词语、同形异义和跨多个 token 的语法；
6. 语气/态度/隐含意义范围与相邻句关系；

至少检查：

- 原文没有被改写；
- token 偏移没有串位；
- 语法和语气字段存在且有原文依据；
- 失败、重试和缓存状态正确；
- 文章重启后仍能读取；
- API 密钥不出现在浏览器响应和日志中。

## 七、首个版本的停止规则

以下能力先不加入 P1/P2，除非真实使用证明它们是阻塞点：

- 无限并发；
- 公网部署；
- 登录和多设备同步；
- 图片/OCR/PDF；
- 任意网页自动抓取；
- 复杂的学习积分和社交功能。

先确保每天打开工具时，分析、理解和复习这条链路足够顺畅。
