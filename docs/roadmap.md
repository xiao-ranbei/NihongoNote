# 迭代路线图

**目标**：先做一个能长期自用的本地学习闭环，再扩展到多人音色、评分和 Agent。

## 一、阶段总览

| 阶段 | 主要交付 | 估算周期 | 完成标志 |
| --- | --- | --- | --- |
| P0 验证和骨架 | 样本集、项目骨架、provider 配置、最小存储 | 1-2 天 | 能在本机启动并成功完成一次结构化分析 |
| P1 交互式解析 | 文章阅读器、分词、句子/词语解析、对话分析、长文任务 | 5-10 个工作日 | 三类真实材料通过验收 |
| P2 朗读和跟读 | TTS、逐句播放、MediaRecorder、录音保存/回听 | 3-5 个工作日 | 朗读和录音可关联到句子并跨重启回放 |
| P3 自用质量 | 历史搜索、删除/导出、重试、缓存、提示词版本、错误体验 | 5-10 个工作日 | 连续使用一周不需要手工修复数据 |
| P4 扩展 | 多角色音色、语气控制、对齐和评分、Agent/skill、浏览器扩展 | 按需 | 以真实学习收益为准，不预设一次完成 |

周期是单人开发、使用现成云服务、没有公网账号体系的粗略估算。模型选型和音色试验可能增加时间。

## 二、P0：验证和骨架

当前已收录两篇真实商务对话，见[日语解析评估样本集](evaluation-corpus.md)。P0 仍需要至少一篇普通文章或不同题材材料，以避免模型只针对商务敬语场景优化。

### 工作项

- 收集至少三篇真实材料；
- 选一个 LLM 候选和一个 TTS 候选做质量/费用 A/B；
- 建立 TypeScript 前后端骨架；
- 建立 SQLite 文档、segment、分析和音频元数据表；
- 配置 `.env` 示例，禁止把真实密钥写入仓库；
- 实现一个最小的结构化分析请求和 schema 校验。

### 不做

- 不做复杂 UI；
- 不做用户系统；
- 不做公网部署；
- 不做发音评分。

### 退出条件

- 一篇短文章能返回可校验 JSON；
- 返回结果能准确关联到句子 ID；
- API 错误不会被伪装成成功；
- 供应商和模型可以通过环境变量切换。

## 三、P1：交互式解析

### 交付顺序

1. 粘贴、编辑和保存文章；
2. 日语句子切分和形态素 token；
3. 句子级阅读器和稳定高亮；
4. 词语/助词/语法卡片；
5. 句子语气、礼貌、潜台词和对话接话理由；
6. 角色识别和手工修正；
7. 长文分块、进度、失败段重试；
8. 历史文章详情。

### 质量门槛

- 不以模型返回的 Markdown 位置绑定 token；
- 对相同词语重复出现的句子，点击位置不能串到另一处；
- 不确定解释必须可见；
- 一段失败不会清空已经完成的段落。

## 四、P2：朗读和跟读

### 第一版能力

- 默认一个标准东京式日语音色；
- 按句子/段落懒生成和缓存；
- 保留标点、换行和对话轮次的停顿；
- 播放、暂停、从当前句开始；
- 浏览器录音；
- 保存录音元数据和文件；
- 在当前文章和历史文章中回放。

### 明确不承诺

- 自动发音评分；
- 自动识别音调错误；
- 多角色真人级演绎；
- 所有浏览器都支持相同录音格式。

## 五、P3：可长期使用的质量增强

- 搜索标题、原文和标签；
- 文章重命名、删除和批量清理音频；
- 导出 JSON、原文和录音；
- 分析缓存和费用统计；
- provider 限流、超时和断点续跑；
- 允许切换 N5-N1/自动难度；
- 允许用户修正角色和词义，并保留修正记录；
- 用固定回归样本检查 prompt 或模型升级后的结果。

## 六、P4：后续扩展

### 多角色朗读

- 角色到 voice 的映射；
- 每个角色独立的语速、音高和停顿；
- 对话段落混音或连续播放；
- 记录生成参数，保证历史音频可追溯。

### 影子跟读增强

- 参考音频和用户录音按句子对齐；
- 显示开始/结束偏差；
- 再评估是否引入发音或声调评分；
- 评分结果必须标记为辅助反馈，不冒充语言教师的绝对结论。

### Agent/skill

- 将结构化分析协议提取为可复用 skill；
- 从 Web 阅读器把当前句子发送给 Agent 深入追问；
- 批量处理收藏文章；
- 保持与 Web API 相同的 schema 和版本控制。

### 浏览器扩展

- 用户在网页中选中文字；
- 发送到本机 Web API；
- 在侧边栏展示解析，不直接把 API 密钥放进扩展；
- 必须单独评估网页权限和隐私风险。

## 七、验收和回归计划

每次更换模型、提示词、分词器或 TTS 时，重新运行固定样本：

1. 助词多、活用复杂的文章；
2. 委婉拒绝、缓和表达和省略主语的对话；
3. 长文分块和中途失败场景；
4. 重复词语和同形异义场景；
5. 录音权限拒绝、空录音和文件损坏场景。

至少检查：

- 原文没有被改写；
- token 偏移没有串位；
- 语法和语气字段存在且有原文依据；
- 失败、重试和缓存状态正确；
- 文章重启后仍能读取；
- 音频和录音删除不会遗留不可见文件；
- API 密钥不出现在浏览器响应和日志中。

## 八、首个版本的停止规则

以下能力先不加入 P1/P2，除非真实使用证明它们是阻塞点：

- 发音评分；
- 无限并发；
- 公网部署；
- 登录和多设备同步；
- 图片/OCR/PDF；
- 任意网页自动抓取；
- 复杂的学习积分和社交功能。

先确保每天打开工具时，分析、理解、听读、跟读和复习这条链路足够顺畅。
