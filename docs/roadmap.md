# 迭代路线图

**目标**：先做一个能长期自用的本地学习闭环，再扩展到 Agent、浏览器扩展和多设备同步。
**更新**：2026-08-27，确定 DeepSeek OpenAI-compatible API 为首条 LLM 实现路径。

## 一、阶段总览

| 阶段 | 主要交付 | 估算周期 | 完成标志 |
| --- | --- | --- | --- |
| P0 验证和骨架 | 样本集、项目骨架、DeepSeek/OpenAI-compatible provider、结构化分析 API、最小存储 | 1-2 天 | 能在本机启动并成功完成一次结构化分析 |
| P1 交互式解析 | 连续文章阅读器、分层标注、混合材料区块、句子/词语解析、对话分析、可取消长文任务、学习库 | 待按编辑器复杂度重新估算 | 三类真实材料和标注交互通过验收 |
| P2 自用质量 | 扩展搜索/批量管理、删除/导出、缓存、提示词版本、错误体验 | 5-10 个工作日 | 连续使用一周不需要手工修复数据 |
| P3 扩展 | TTS 标准朗读/播放、Agent/skill、浏览器扩展、多设备同步或公网部署 | 按需 | 以真实学习收益为准，不预设一次完成 |

周期是单人开发、使用现成云服务、没有公网账号体系的粗略估算。当前 P1 新增了范围渲染、编辑版本和学习库交互，具体周期要在技术拆分和原型验证后重新估算；模型选型可能增加时间。

## 二、P0：验证和骨架

当前已收录两篇真实商务对话，见[日语解析评估样本集](evaluation-corpus.md)。P0 仍需要普通文章、课文或混合材料，以避免模型只针对商务敬语场景优化。

### 工作项

基础骨架、DeepSeek OpenAI-compatible adapter、JSON schema 校验、句段分析任务、进度和失败句段重试已经实现；以下工作仍需真实供应商 key 验证。

- 收集至少三篇真实材料；
- 以 DeepSeek OpenAI-compatible API 作为首个 LLM 候选，使用真实材料做质量/费用验证；
- 记录 provider、protocol、model、promptVersion、用量和错误分类。

### 不做

- 不做复杂 UI；
- 不做用户系统；
- 不做公网部署；

### 退出条件

- 一篇短文章能返回可校验 JSON；
- 返回结果能准确关联到句子 ID；
- API 错误不会被伪装成成功；
- DeepSeek 可以通过环境变量配置并完成一次真实分析；
- provider 和模型可以通过环境变量切换，未实现协议会明确报错；
- 空 JSON、非法 JSON 和长度截断都会进入失败/重试路径。

### P0 的协议边界

- DeepSeek OpenAI-compatible 是 P1 的必做路径；
- Anthropic-compatible 先只写入 adapter 设计，不要求在 P0 完成；
- 不允许业务层直接依赖 OpenAI 或 Anthropic SDK 的响应对象；

## 三、P1：交互式解析

### 交付顺序

1. 接入并验证 DeepSeek OpenAI-compatible adapter 和分析 API（基础链路已完成，待真实 key 验证）；
2. 粘贴、编辑和保存文章，自动识别文章类型并生成可手动调整的内容区块；
3. 日语句子切分、形态素 token 和稳定的 UTF-16 偏移；
4. 连续文章阅读框，保留原文、换行、标点和未解析区块；
5. 背景范围与线型标注：句子底色、普通词/助词/功能词/副词分类色块、语法覆盖色块、单/双/虚线下划线、单/双波浪线及副词独立线色；不为分句设置独立色块；
6. 悬浮只高亮当前范围、不显示弹窗；点击打开锚点解析卡片并按“句子结构 → 词语 → 语法 → 语气”四层循环，缺少的层级自动跳过；
7. 句子通用解析、语气/态度/隐含意义，以及分析时一次生成的当前句旁对话相邻句关系标签/原因和可展开的关系箭头；
8. 用户手动启动 AI 分析，显示进度，支持取消后续跑和失败句段重试；
9. 角色识别、区块/分句/标注范围人工修正，并保留 AI 原始版本；
10. 可折叠学习库、搜索、内容类型/分析状态筛选和偏好持久化。

### 质量门槛

- 不以模型返回的 Markdown 位置绑定 token；
- 对相同词语重复出现的句子，点击位置不能串到另一处；
- 不确定解释必须可见；
- 一段失败不会清空已经完成的段落；
- 文章在一个连续阅读框中显示，不能因内部句段任务而拆成视觉卡片；
- 句子底色、词语类别色块和语法色块按确定层级叠加，不为分句增加独立色块；
- 线型、图例和颜色共同表达普通词、助词、功能词、副词、多词语法及语气/态度；
- 同一位置重复点击按句子结构、词语、语法、语气循环并跳过不存在的层级，点击其他位置重置，触屏端无需 hover；
- 锚点卡片在视口边缘自动换位，且不会遮挡触发位置的关键原文；
- 标题/注释默认不解析，正文/日语例句默认解析，混合区块可以手动调整；
- 对话关系默认仅显示当前句相邻关系，普通文章不出现无依据的回复理由；
- 取消分析保留已完成结果，重新启动只处理待分析或失败句段；
- 人工修正重新分析后仍可查看 AI 原始版本和用户版本；
- 学习库折叠状态跨刷新保留，搜索和筛选条件结果正确。

## 四、P2：可长期使用的质量增强

- 扩展搜索、标签和批量管理（首版只承诺搜索和内容类型/分析状态筛选）；
- 文章重命名和删除；
- 导出 JSON 和原文；
- 分析缓存和费用统计；
- provider 限流、超时和断点续跑；
- 在 P1 稳定后评估并实现 Anthropic-compatible adapter；
- 允许切换 N5-N1/自动难度；
- 扩展修正历史、范围冲突提示和批量应用能力；
- 用固定回归样本检查 prompt 或模型升级后的结果。

## 五、P3：后续扩展

### TTS 标准朗读（待排期）

- 接入独立的 TTS provider；
- 标准、清晰的日语发音；
- 按句子或段落播放、暂停、继续和从当前句开始；
- 根据标点、普通排版换行和对话轮次产生合理停顿；
- 支持语速调整；
- 记录生成参数并按文本和参数缓存；
- 不包含浏览器录音、跟读录音、录音保存或录音回放。

### Agent/skill

- 将结构化分析协议提取为可复用 skill；
- 让 Web 后端和 Agent 共用 provider-neutral 的分析 schema；
- 从 Web 阅读器把当前句子发送给 Agent 深入追问；
- 批量处理收藏文章；
- 保持与 Web API 相同的 schema 和版本控制。

### 浏览器扩展

- 用户在网页中选中文字；
- 发送到本机 Web API；
- 在侧边栏展示解析，不直接把 API 密钥放进扩展；
- 必须单独评估网页权限和隐私风险。

## 六、验收和回归计划

每次更换模型、提示词或分词器时，重新运行固定样本：

1. 助词多、活用复杂的普通文章或课文；
2. 标题、例句、注释和正文混合的教材材料；
3. 委婉拒绝、缓和表达和省略主语的对话；
4. 长文分块、取消和中途失败场景；
5. 重复词语、同形异义和跨多个 token 的语法；
6. 语气/态度/隐含意义范围与相邻句关系；

至少检查：

- 原文没有被改写；
- token 偏移没有串位；
- 语法和语气字段存在且有原文依据；
- 失败、重试和缓存状态正确；
- 文章重启后仍能读取；
- API 密钥不出现在浏览器响应和日志中。

## 七、首个版本的停止规则

以下能力先不加入 P1/P2，除非真实使用证明它们是阻塞点：

- 无限并发；
- 公网部署；
- 登录和多设备同步；
- 图片/OCR/PDF；
- 任意网页自动抓取；
- 复杂的学习积分和社交功能。

先确保每天打开工具时，分析、理解和复习这条链路足够顺畅。
